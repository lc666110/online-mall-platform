## 重要审计项与修复

1. **旧商品表单覆盖销售库存**：上下架改为专用 PATCH，只写 active；普通资料编辑不写未改动库存；显式库存调整使用 expected_stock 并发冲突检测。回归测试模拟打开表单后库存扣减，验证资料保存保留库存、旧库存调整409、新读取调整成功。
2. **缓存删除后旧请求回填**：商品/购物车使用 MySQL 提交版本选择 Redis 键，删除/结算/编辑事务递增版本；读取商品时检查当前上架状态。测试注入晚到的旧缓存，验证购物车项不会复活、下架详情不会返回。SKU 价格和库存实时从 MySQL 获取。
3. **购物车/下单锁顺序**：统一同用户 users 行锁在先。测试并发10次加购、加购与结算竞争，验证数量不丢失、无死锁；多用户竞争最后一件库存只有一单成功。
4. **代理 IP 信任**：默认不信任任何转发源；Compose 仅信任指定专用子网，Nginx 覆盖客户端转发头。测试可信代理、非可信来源与默认配置的 ClientIP。
5. **测试环境互相污染**：后端测试拒绝数据库名称未以 `_test` 结尾的 DSN，强制使用 Redis DB15；本机应用默认 DB0。清理此前测试回填的缓存，浏览器交易重新通过。运行其他应用/环境也应使用独立 Redis 实例/逻辑库。
6. **结算表单丢失输入**：修改购物车数量刷新数据时不重建收货表单，完整浏览器交易流程通过。
7. **密码字节上限**：除字符数量外，校验 bcrypt UTF-8 72字节限制，超长多字节密码返回400。
8. **移动长分类名**：分类按钮约束宽度和换行；真实添加73字符长分类，在390px宽屏检查 document.scrollWidth，再删除测试分类，测试通过。
9. **依赖漏洞**：升级 x/net、x/text、x/crypto、quic-go、MySQL driver 和 Sonic，更新 go.mod/go.sum；全量后端和安全检查重跑。

## 已验证权限与交易边界

普通用户后台访问403；staff 用户权限接口403；资料更新不能通过额外 role 字段提权；禁用账号当前 JWT 立即失效；退出会话不可继续访问。非本人订单读取/修改404；未完成订单不能评价，重复评价409；重复取消/售后批准不能重复返库存。后端结算计算真实总额，客户端不能指定价格；幂等提交只扣减一次。

## 尚未验证的环境

本机没有 Docker daemon，因此没有宣称镜像启动/目标宿主容器业务流程通过。仓库 CI 配置包含真实服务测试和 Docker build，实际 GitHub Actions 结果以仓库运行记录为准。默认 Dashboard 的 ECharts 延迟加载块约194KB gzip，Vite 有500KB未压缩块提示；其余路由独立加载，没有隐藏构建警告。

没有获得公网主机/域名/证书，本次交付为本地运行系统及部署源码。未实施公网压力/容量、TLS代理、外部支付、退款网关、短信邮件、物流平台和灾备验收。正式上线请按 [deployment.md](deployment.md) 在目标宿主完成这些适用项；人工付款和整单售后边界见架构文档。
